# 前端接口与样式整改实施计划 v0.2

## 1. 目标与范围

- 范围：Workbench 主页面及其弹窗组件（StyleManager / PluginWorkshop / ModelSettings / ApprovalCard）。
- 目标：
  1. 将关键业务从模拟数据切换为真实后端接口；
  2. 补齐 PRD 要求的关键控件与状态交互；
  3. 完成三栏工作台样式一致性与可读性整改。

## 2. 现状差距摘要

### 2.1 接口对接差距（高优先）

1. Agent 会话仍以本地模拟消息为主，未完整接入生成任务创建、轮询/流式状态、结果应用。
2. StyleManager 组件未接入 styleApi（列表、创建、更新、切换、样文分析均未闭环）。
3. PluginWorkshop 组件仍为静态插件卡，未按项目挂载状态回显与更新。
4. ModelSettings 组件未接入 modelApi（provider/key/policy 的真实 CRUD 未串接）。
5. ApprovalCard 主要使用模拟数据，未完整接入审批列表与 approve/reject 回写。

### 2.2 控件与交互差距（中高优先）

1. 文风切换“强提醒”缺少后端 warningConfirmed 语义闭环。
2. AI 生成流的状态机不完整（创建中 / 流式中 / 可应用 / 失败）。
3. 审批卡片缺少“处理中禁用态、成功态回刷列表”。
4. 插件挂载状态未统一到 Workbench 顶部/输入区回显。

### 2.3 样式差距（中优先）

1. 左中右面板宽度比例与折叠态在窄屏下可读性下降。
2. 按钮/输入/状态色在不同组件间存在风格漂移。
3. 聊天区、工具栏、状态栏层级与对比度有局部不足。

---

## 3. 三阶段实施计划

## 阶段 1：真实接口对接（优先级 P0）

### 3.1 StyleManager

- 对接接口：
  - `GET /v1/novels/{projectId}/styles`
  - `POST /v1/novels/{projectId}/styles?operatorId=`
  - `PUT /v1/novels/{projectId}/styles/{styleId}?operatorId=`
  - `POST /v1/novels/{projectId}/styles/switch?operatorId=`
  - `POST /v1/novels/{projectId}/styles/analyze-sample?operatorId=`
- 动作：
  - 弹窗打开加载 style 列表并回显默认风格；
  - 保存时按“已有 styleId -> update；无 styleId -> create”；
  - 切换默认风格走 switch，并传 warningConfirmed；
  - 样文分析调用 analyze-sample 后回填 pace/tone/narrativeFocus 建议。

### 3.2 PluginWorkshop

- 对接接口：
  - `GET /v1/plugins/catalog`
  - `GET /v1/novels/{projectId}/plugins`
  - `POST /v1/novels/{projectId}/plugins/install?operatorId=`
  - `PATCH /v1/novels/{projectId}/plugins/{pluginCode}?operatorId=`
  - `DELETE /v1/novels/{projectId}/plugins/{pluginCode}?operatorId=`
- 动作：
  - catalog 与 project installs 归并，形成“可安装 + 已安装 + enabled”统一视图；
  - 安装/启停/卸载成功后局部更新卡片状态，并同步 Workbench 已挂载标签。

### 3.3 ModelSettings

- 对接接口：
  - `GET /v1/model/providers`
  - `GET /v1/model/providers/{providerCode}/models`
  - `GET /v1/model/keys?userId=`
  - `POST /v1/model/keys?userId=&operatorId=`
  - `PATCH /v1/model/keys/{keyId}?userId=&operatorId=`
  - `GET /v1/novels/{projectId}/model-policies`
- 动作：
  - 以已配置 key + provider model 组合生成模型列表；
  - 保存配置时创建或更新 key，并回刷“连接状态”；
  - 使用 policy 列表回显项目默认策略。

### 3.4 Agent + Approval

- 对接接口：
  - Agent：`conversations`、`messages`、`generations`、`generations/{taskId}`、`apply`
  - Approval：`approvals`、`approvals/{id}/approve`、`approvals/{id}/reject`
- 动作：
  - 发送指令 -> 创建 generation 任务 -> 轮询/流式拉取状态 -> 结果入消息列表；
  - apply 后将产出合并到编辑区并刷新版本/字数；
  - 审批卡片操作完成后回写 resolved 状态并刷新审批列表。

### 阶段1验收标准

- 不再依赖硬编码模拟消息/模拟插件/模拟文风保存。
- 关键动作有统一错误提示（含 traceId）与 loading 反馈。

---

## 阶段 2：控件与交互补齐（优先级 P1）

1. Agent 状态机：待发送/生成中/可应用/失败重试。
2. 审批卡片：提交中禁用按钮，成功显示“已归档/已拒绝”。
3. 文风切换强提醒：用户确认后才调用 switch。
4. 插件挂载状态：右侧输入区与插件工坊状态一致，支持即时回显。
5. 版本操作联动：apply / save 后自动刷新版本列表。

### 阶段2验收标准

- 单次写作链路（发指令->生成->应用->审批）可完整闭环。
- 所有关键按钮具备防重入与反馈状态。

---

## 阶段 3：样式整改与可用性收口（优先级 P2）

1. 三栏布局比例统一：左 280 / 右 340 / 中自适应，窄屏降级策略明确。
2. 折叠态可点击区域、阴影、边框统一。
3. 按钮、输入框、状态标签色板统一（success/warn/error/info）。
4. 聊天气泡、审批卡、工具栏文字对比度提升。
5. 弹窗层级与背景模糊强度统一，避免视觉噪声。

### 阶段3验收标准

- 1366 与 1920 主流分辨率下无主要布局错位。
- 交互态（hover/active/disabled/loading）表现一致。

---

## 4. 联调检查清单

1. 必备参数：projectId、operatorId、userId 缺失时均有前端兜底提示。
2. 错误处理：401 刷新 token、业务错误 message、traceId 可追踪。
3. 数据一致性：
   - 插件挂载状态 = 服务端 install 列表；
   - 当前文风 = 默认 style + switch 结果；
   - 审批状态 = approvals 列表与卡片 resolved 一致；
   - 章节内容与版本记录一致。

## 5. 执行顺序

1. 先完成阶段1（接口对接）并走一轮联调。
2. 再完成阶段2（交互状态机）保证写作主链路可用。
3. 最后完成阶段3（样式收口）并做端到端回归。
