# PenMate UI/UX 全量重构决策基线

> 日期：2026-07-21
> 状态：已确认，正在实施
> 范围：前端全部用户界面，以及为新交互闭环所需的后端领域、接口、持久化和实时事件调整

## 1. 产品定位与总体原则

### 1.1 核心用户

PenMate 首先服务长期维护多卷、多角色和复杂设定的中文长篇作者。

产品应表现为专业创作工作台：安静、清晰、紧凑、高效。AI 是核心协作者，但正文编辑仍是主工作台的中心任务。

### 1.2 视觉方向

- 放弃当前全局“古风仙侠、金色发光、深色玻璃”视觉。
- 采用“现代专业写作工具 + 克制的东方文字气质”。
- 以清晰排版、纸张感编辑区和中性色为主，朱红或墨绿仅作少量强调。
- 避免书法字体、发光边框和装饰纹样干扰高频创作。
- 支持完整浅色与深色主题，默认跟随系统，并允许手动切换。
- 浅色主题使用柔和纸白，深色主题使用中性炭黑；两套主题保持一致的信息层级和对比度。

### 1.3 实施顺序

全量重构分阶段落地，但必须先建立统一设计系统：

1. 主工作台与 Story Bible。
2. 书架、作品创建和首次进入流程。
3. 模型与个人设置；文风和插件只保留必要入口，不纳入重构。
4. 登录与账户；注册、邮箱验证和忘记密码延期。
5. 管理员工作台。
6. 官网首页。

核心验收闭环是：创建作品 -> 写作 -> AI 协作 -> AI 正式编辑 -> 自动保存 -> 安全撤回。

## 2. 主工作台信息架构

### 2.1 三栏结构

主工作台保留三栏，并允许用户拖拽调整大小：

- 写作模式：作品目录 / 正文编辑 / AI 协作。
- Story Bible 模式：设定导航 / 设定详情 / AI 协作。

左栏应明显窄于当前实现，默认目标宽度约 180-240px。三栏宽度、折叠状态和布局预设需要被持久化。

### 2.2 布局预设

提供三个一键布局：

- 均衡：紧凑目录 + 大编辑区 + AI。
- 专注写作：隐藏目录和 AI，只保留正文。
- AI 协作：收起目录，正文与 AI 接近对半。

用户仍可自由拖拽微调；双击分隔线恢复默认宽度。

- 作品目录和 AI 栏均可通过图标按钮独立完全折叠，正文栏始终保留。
- 作品目录宽度约束为 `160–360px`，AI 栏约束为 `300–600px`，正文区域至少保留约 `520px`。
- 屏幕不足以满足三栏最小宽度时先自动折叠作品目录；继续变窄时进入移动端单视图切换。
- 折叠后在项目栏保留目录和 AI 图标，可一键恢复。
- 双击分隔线恢复当前布局预设；键盘用户可通过按钮按固定步长调整宽度。
- 选择布局预设时覆盖当前栏宽，之后仍可继续手动调整。

### 2.3 右侧 AI 面板约束

右侧 AI 面板现有结构不做重新设计，不调整消息、运行详情或会话历史的信息层级。

只接入本次新增能力：

- `chapter_edit` Tool 实时事件。
- 当前章节 AI 锁定状态。
- 多章节编辑结果。
- 24 小时 AI 修改撤回。

## 3. 作品目录

### 3.1 命名与信息密度

- 左栏名称从“大纲”改为“作品目录”。
- 章节行常态只显示章节序号和标题。
- 当前章节不额外显示字数；字数归编辑器展示。
- 卷标题不增加干扰性统计。
- 新建、重命名、移动、删除只出现在右键菜单。
- 顶部保留搜索入口。
- 作品目录不显示 AI 修改或 AI 撤回标记。

### 3.2 拖拽

- 支持卷、章节拖拽排序和章节跨卷移动。
- 拖拽时显示清晰插入位置。
- 移动完成后提供短暂的“撤销移动”。
- 右键菜单保留精确移动入口。

### 3.3 后端结构重构

当前 `novel_outline_nodes` 与 `novel_volumes / novel_chapters` 重复表达卷章结构，且现有前端创建的“卷”实际上只写入大纲节点，章节 `volumeId` 仍可能为空。

已确认的新结构：

- `novel_volumes + novel_chapters` 是作品目录的唯一数据源。
- `novel_outline_nodes` 不再承担卷章层级。
- 不保留独立章纲模块，也不迁移或继续使用 `novel_outline_nodes.content`。
- 新增统一目录移动接口，在单个数据库事务中完成移动、同级重排和结构修订号更新。
- 服务端返回最终目录结构，前端不自行猜测最终排序。

## 4. 正文编辑器

### 4.1 内容模型

- 中央编辑器只用于小说正文。
- 正文唯一标准为 UTF-8 纯文本。
- 删除加粗、斜体、引用、标题等 Markdown 或富文本操作。
- 不承担旧章节或旧版本兼容；项目尚未上线，可以同步调整前后端数据结构。

### 4.2 编辑能力

第一版包含：

- 查找与替换。
- 当前段落高亮。
- 打字机模式。
- 专注模式。
- 字号、行高、段间距和编辑区宽度调节。
- 中文标点自动配对。
- 实时字数、选中字数和光标位置。
- 自动保存状态与离线状态。
- 撤销、重做。
- AI 锁定、流式编辑和撤回状态。

不加入富文本、Markdown、拼写检查或复杂排版。

### 4.3 删除旧功能

- 删除章节版本列表、查看、创建、恢复及对应后端接口和数据结构。
- 删除“发布章节”及发布状态。
- 不引入“未开始 / 写作中 / 待修订 / 已定稿”等章节状态。
- 保存只表示将当前章节正文同步到后端。

### 4.4 前端撤销与崩溃恢复

- 用户普通输入的撤销/重做只在当前编辑会话有效。
- 页面刷新或关闭后清空普通撤销历史。
- 使用成熟纯文本编辑器引擎的事务历史，不继续维护当前手写的双数组快照。
- 使用 IndexedDB 保存崩溃恢复草稿，不再仅保存裸 `localStorage` 字符串。
- 写作辅助状态与正文内容分开存储。

### 4.5 编辑器底层

- 正文编辑器由原生 `textarea` 和手写全文快照改为 CodeMirror 6。
- CodeMirror 只承载 UTF-8 纯文本，不启用 Markdown、富文本节点或代码编辑能力。
- 使用其事务历史、选区、光标、键盘映射、查找替换和增量更新能力。
- 当前段落高亮、AI 未提交预览和锁定状态通过编辑器装饰层实现，不写入正文内容。
- 中文输入法、复制粘贴、撤销重做和长章节性能必须纳入编辑器专项测试。
- 不使用 Monaco；不引入 ProseMirror 或 Tiptap。

## 5. 正文存储与自动保存

### 5.1 正式存储

- PostgreSQL `TEXT` 字段保存当前章节正文，并作为唯一正式数据源。
- `content_revision` 继续保留，但只用于并发控制，不代表可浏览历史版本。
- 移除章节正文的预签名上传、OSS 正文读取和正文对象元数据链路。
- OSS 只用于作品封面、导入导出文件、附件或系统备份。

### 5.2 自动保存节奏

- 内存状态：每次输入立即更新。
- IndexedDB 本地暂存：停止输入 250ms 后写入。
- PostgreSQL 正式保存：停止输入 1000ms 后提交。
- 持续输入时：最迟每 5 秒同步一次。
- 切换章节、窗口失焦、启动 AI、`Ctrl+S`：立即同步。
- 保存请求串行执行；请求进行中时合并后续变化，不并发提交旧正文。
- 界面状态统一为：本地暂存、正在同步、已保存、保存失败、离线。

## 6. 章节编辑并发与租约

### 6.1 编辑者模型

用户和 AI 都是正式章节编辑者，遵守相同的写入规则。同一章节同一时刻只有一个编辑者。

建议的租约字段至少包含：

```text
ownerType
ownerId
leaseToken
expiresAt
expectedRevision
```

正式租约和正文写入以 PostgreSQL 校验为准。Redis 可用于运行状态、通知或缓存，但不能单独决定最终写入是否合法。

### 6.2 写入校验

所有用户、AI 和内部工具的章节正文写入必须统一经过同一应用服务，并携带：

```text
chapterId
leaseToken
expectedRevision
newContent
```

最终更新必须在单个数据库事务中校验项目权限、租约归属、租约有效期和修订号，并原子增加 `content_revision`。

不能让数据库行锁跨越整个 LLM 生成过程。AI 运行期间使用可续期逻辑租约；最终提交时才进行短事务更新。

### 6.3 主要行为

- 启动 AI 编辑前先刷新本地自动保存队列。
- 本地同步失败时不能启动 AI 编辑。
- AI 获得章节租约后，用户不能修改该章，但可以编辑其他章节。
- 同一章不能同时被两个 AI Run 编辑。
- 取消、失败或租约超时不提交半成品。
- 取消后即使迟到的模型结果返回，也必须因租约失效而无法写入。
- 多标签页或多设备打开同一章时只有一个可编辑，其他实例只读；接管后旧令牌失效。

## 7. AI 章节编辑 Tool

### 7.1 Agent 自主性

- Agent 具有较大自主性，可以自行判断是否修改章节。
- 不增加编辑意图预检、一次性语义许可或可见的“问答 / 编辑”模式。
- 是否调用 `chapter_edit` 主要由清晰的 Tool 描述引导。
- 后端权限、租约和修订检查只保证数据安全，不限制 Agent 的创作判断。

该选择的已知代价是：Tool 描述不能保证模型永远符合用户预期，Agent 可能主动修改用户原本只想讨论的内容。停止、失败不提交和 AI 撤回是主要安全网。

### 7.2 Tool 边界

当前使用缓冲式模型调用的 `draft_generation` 应演进为拥有完整章节编辑职责的 `chapter_edit`：

1. 获取章节 AI 租约。
2. 读取正文和修订号。
3. 流式调用模型。
4. 发布正文预览事件。
5. 成功后原子保存最终正文。
6. 保存 AI 撤回记录。
7. 释放租约。

Tool 产生结构化业务事件，前端负责视觉展示：

```text
chapter.edit.started
chapter.edit.delta
chapter.edit.completed
chapter.edit.failed
chapter.edit.cancelled
```

### 7.3 实时编辑表现

- AI 编辑期间中央编辑器实时展示生成内容，但内容在成功前只是未提交预览。
- 整个编辑器进入只读锁定态，而不是只显示顶部提示。
- 编辑器整体降低亮度和饱和度，并出现清晰、克制的 AI 编辑边框。
- 原正文降低对比度，AI 新输出保持可读，并带有明确的 AI 标识。
- 用户可以停止任务；停止、失败时恢复原正文。
- 成功后一次性保存最终内容，再恢复用户编辑权。

### 7.4 多章节任务

- 一个 Agent 任务允许修改多个章节。
- 同一时刻只锁定和处理一个章节，按章节依次提交。
- 每个章节独立保存结果与撤回能力。

## 8. AI 修改撤回

### 8.1 用户输入与 AI 修改分工

- 用户普通输入：只使用前端当前会话撤销/重做和 IndexedDB 崩溃恢复。
- AI 正式修改：前端记录为一个撤销单元，同时在 PostgreSQL 保存 24 小时撤回记录。
- 后端不为用户普通输入提供通用撤销/重做。
- Redis 不保存 AI 撤回正文的权威副本。

### 8.2 持久化

AI 修改前正文必须与最终正文更新处于同一个 PostgreSQL 事务。撤回记录至少包含：

```text
operationId
runId
chapterId
beforeContent
resultContentHash
sequenceNo
status
createdAt
expiresAt
```

接口必须检查记录未过期，并确认当前正文仍处于可撤回链路上。过期记录由定时任务清理；不要求第 24 小时整点物理删除。

### 8.3 展示与组合规则

- 作品目录不显示 AI 修改标记。
- 撤回入口出现在当前章节的编辑器状态区，以及对应对话 Tool 卡片中。
- 两处引用同一个 `operationId`，状态同步。
- 同一 `runId + chapterId` 的多次 Tool 调用合并为一个撤回单元，恢复到该任务第一次编辑此章之前。
- 不同 Run 对同一章的修改形成栈，只能从最新修改开始依次撤回。
- 一次任务修改多个章节时，每章独立撤回；全部仍可撤回时可以撤回本次全部修改。
- 多章任务中任一章已被用户修改时，禁用“全部撤回”，但其他章节仍可逐章撤回。
- 用户开始手动修改 AI 结果后，该章的后端“撤回 AI 修改”立即失效，避免删除用户的新内容；只保留编辑器顺序撤销。

这不是通用章节版本历史，只是限时的 AI 操作审计与回滚。

## 9. Story Bible

### 9.1 工作区结构

- 保持顶层“写作 / Story Bible”模式切换。
- Story Bible 内部由原来的导航、节点列表、节点编辑三列，合并为主工作台的两列：设定导航 / 设定详情；右侧 AI 继续作为第三列。
- 左侧合并语义类型、分类、标签、搜索和节点列表。

### 9.2 节点类型与日常编辑

- 默认提供角色、地点、组织、物品、世界规则、事件、线索等常用类型。
- 作者可以新增自定义类型和字段，但只填写名称、图标、颜色和字段定义。
- `semanticFamily`、Schema、路由模式和模型配置放入高级设置，默认隐藏。
- 分类和标签保留为日常整理工具。

### 9.3 关系

- 增加二维交互关系图，并保留紧凑列表用于精确编辑。
- 可以按类型筛选关系，点击节点进入详情。
- 新增关系仍使用表单，不在图上实现复杂拖线。
- 关系类型显示“盟友、敌对、隶属、位于”等可读名称，不要求作者输入 `ALLY_OF` 等代码。

### 9.4 状态演化

- 前端彻底隐藏 RFC 6902 JSON Patch。
- 作者只编辑生效章节、结束章节、变化摘要，以及增加、修改、删除的属性。
- 当前章节有效状态以可读字段列表展示。
- JSON Patch 可以继续作为后端内部存储格式。

### 9.5 审批与历史

- 用户手动修改 Story Bible 不需要审批。
- AI 新增或改变角色身份、关系、世界规则等稳定设定时继续需要审批。
- 保留 Story Bible 变更审计，但不提供任意版本恢复。
- 历史显示操作者、时间、变更摘要、AI 来源 Run 和审批结果；技术修订号默认隐藏。

## 10. 书架与作品生命周期

### 10.1 书架展示

- 支持封面网格与紧凑列表两种视图，默认网格。
- 提供搜索和排序，并保存视图偏好。
- 卡片展示封面、书名、简介、总字数、章节数和最后编辑时间。
- 作品封面支持可选上传，图片存储在 OSS。
- 未上传封面时生成克制的文字封面，不使用随机渐变。

后端必须正式支持并聚合书架所需的简介、类型、标签、总字数、章节数和最后编辑时间，不能继续依赖前端空值回退。

### 10.2 创建作品

- 作品名必填；类型、简介、标签和封面可选。
- 创建成功后自动生成“第一卷”和“第一章”。
- 创建后直接进入第一章编辑器，不展示完全空白的工作台。

### 10.3 删除与恢复

- 删除作品改为移入回收站。
- 回收站默认保留 30 天。
- 支持恢复和立即永久删除。
- 普通“移入回收站”只进行一次确认，并在操作完成后提供短暂撤销入口。
- 回收站持续显示每个作品距离自动清理的剩余天数。
- 主动永久删除时必须在高风险确认对话框中输入完整作品名称，不要求再次输入账户密码。
- 确认内容明确列出正文、目录、Story Bible、封面和关联 AI 数据将被删除且不可恢复。
- 确认后作品立即不可访问；后端可以异步清理并显示“正在删除”，期间禁止重复操作。
- 30 天到期后自动清理，不再向用户二次确认。

### 10.4 导入导出

- 整本导出支持 TXT 和 DOCX，按卷章生成标题。
- 导入支持 TXT，自动识别“第X卷 / 第X章”。
- 导入前展示拆分预览并允许调整。
- 第一版 TXT 导入只允许从书架创建一个新作品，不允许追加或覆盖已有作品。
- 导入预览允许调整作品名、卷章拆分和章节标题；确认后一次性创建作品及全部卷章。
- 因为不写入已有作品，第一版不设计同名章节、顺序或正文覆盖冲突的自动合并规则。
- 本期不做 EPUB、PDF 或第三方平台直接发布。

## 11. 设置与管理员工作台

### 11.1 设置归属

- 账号设置：个人模型服务商、个人 API Key、默认模型、外观和安全。
- 作品设置：封面、类型、标签和作品级 AI 默认偏好。
- 工作台顶部只显示当前模型与文风摘要，点击进入对应设置。
- 移除工作台多个重叠的大型设置弹窗，以及个人设置与工作台模型配置的重复入口。

个人设置使用分区导航，不再纵向堆叠大型卡片。分区包括：个人资料、外观与编辑器、AI 模型、默认模型与 Agent 偏好、安全、数据与账户；移动端使用顶部下拉导航。

默认模型与 Agent 偏好中直接展示三个必选模型，不放入高级设置：

- 创作模型：负责主 Agent Loop、Tool 决策、正文生成与改写。
- 上下文筛选模型：负责 `LLM_SELECTOR` 下的 Story Bible 和上下文选择。
- Embedding 模型：负责向量索引与语义检索。

删除 `Worker / Dirty Work Agent` 模型角色及相关无效配置字段。界面不得继续暴露 Main Agent、Worker、Router 等内部命名。

三个账号默认模型不写入用户主表，继续使用与用户一对一的 `model_user_preferences`。该表调整为创作模型、上下文筛选模型和 Embedding 模型三个引用，并删除 Worker 引用。作品级覆盖继续使用 `project_ai_configurations`，补充当前缺失的创作模型引用；三个作品字段为空时分别继承账号默认值，界面明确显示继承来源。

新用户未指定三个默认模型时仍可进入工作台并手动写作，但 AI、Story Bible 上下文筛选和 RAG 暂不可用。用户首次触发 AI 能力时进入三模型必填配置流程，配置成功后再执行原任务。

个人模型 API Key 与官方密钥使用相同规则：保存后不允许再次查看明文，只显示掩码、末四位、更新时间和连通性状态；用户可以替换或删除密钥。个人模型管理同样提供显式“测试连接”按钮，并使用相同的最小真实调用规则。

文风模块暂不纳入本轮重构范围。保留现有后端能力和必要入口，但不新增或重做文风作用域、管理交互和数据结构。

插件模块同样暂不纳入本轮重构范围。保留现有插件能力和入口，不新增或重做插件安装、启用、权限和版本管理交互。

### 11.2 管理员工作台

已确认：

- 新增独立管理员工作台。
- 管理员编辑官方模型与管理员编辑自己的个人模型必须位于不同入口。
- 官方模型进入管理员工作台；个人模型仍在个人设置。
- 当前 RBAC 页面并入管理员工作台，并进行完整 UI/UX 重构。
- 后端现有 `SYSTEM / USER` 模型作用域继续作为权限基础。

管理员工作台第一版包含：

- 总览：用户、作品、Agent 运行和失败任务。
- 官方模型：系统模型、官方密钥、连通性测试和变更影响范围。
- 用户管理。
- 角色与权限：包含菜单访问配置。
- 任务中心：后台任务、失败原因和重试。
- 审计日志：模型、权限和管理员操作记录。

管理员工作台使用可折叠左侧导航承载上述模块，右侧使用高密度表格、筛选器和详情抽屉。总览页优先展示异常与待处理事项，不堆叠装饰性统计卡片。

管理员总览定位为运行治理台，而不是业务增长看板：

- 首屏优先展示失败的 Agent Run、阻塞的后台任务、官方模型连接异常和长期占用的章节租约。
- 展示近 24 小时 Agent 成功率、失败率、运行中数量和模型调用异常趋势。
- 每项异常都必须能够直接进入对应详情或任务中心处理，不能只展示不可操作的数字。
- 用户总数、作品总数和近 7 日活跃用户等业务指标放在次要区域。
- 本轮不制作收入、增长漏斗等缺少真实业务基础的指标。

上述管理员总览是后续产品方向，本轮只实现对应的页面结构和视觉样式。由于当前后端没有统计、异常聚合和总览处置接口，本轮不新增这些接口、不接入真实总览数据，也不使用伪造数据制造已经可用的假象；需要数据的位置使用明确的未接入状态。

RBAC 采用业界常见的暂存后统一保存模式：权限按业务域分组，支持搜索、组级全选和未保存变更提示；用户角色与角色权限通过批量接口在单个事务内原子替换，并记录一条完整审计。角色修订冲突时要求管理员刷新后重新操作，不静默覆盖他人变更。

管理员可以在任务中心强制终止用户的非终态 Agent Run，但必须填写原因。终止操作立即使相关章节租约失效、阻止迟到结果提交，并将管理员、原因和受影响 Run 写入审计；用户侧明确显示任务由管理员终止。

官方模型密钥保存后不得再次回显明文。管理员只能看到掩码、末四位、更新时间和测试状态；可以测试连通性或输入新密钥完成轮换，后端接口不得返回已保存密钥原文。

官方模型管理提供显式“测试连接”按钮。连接测试发起一次最小真实调用：聊天模型发送最短请求，Embedding 模型发送极短文本并校验返回维度；界面显示结果、耗时、测试时间和脱敏错误。测试可能产生极少量模型费用。

官方模型修改或删除立即生效，不引入模型配置修订、运行排空或平滑切换。受影响的非终态 Agent Run 可以直接失败，但必须返回明确的管理员变更原因、释放章节编辑租约，并保证未完成的正文预览不会提交。已经完成并提交的独立 Tool 副作用不自动回滚。

Embedding 模型发生身份或维度变更后，处理流程与用户自行更改模型一致：相关作品直接切换为 `LLM_SELECTOR`，旧向量索引标记为需要重建，但不阻断正文写作或 Agent 使用。系统不自动重建；作品用户后续自行触发重建。重建完成后仍保持 `LLM_SELECTOR`，用户需要自行重新选择语义检索或混合筛选，不记忆也不自动恢复之前的路由模式。

模型配置不拆分为“连接 + 模型”两层。每个官方或个人模型配置继续独立保存服务商、Base URL 和 API Key；即使多个模型使用同一服务商，也不共享单独的连接或凭据对象。保留现有 `display_name` 作为用户可填写的展示名称；未填写时由界面和后端回退到真实模型 ID，模型选择器优先显示展示名称并同时提供真实模型 ID 供辨认。

官方模型和个人模型采用相同的“紧凑列表 + 右侧编辑抽屉”交互，但入口和数据作用域严格分离：

- 列表按聊天模型和 Embedding 模型分组。
- 每行显示展示名称、服务商、真实模型 ID、密钥掩码、启用状态和最近一次测试结果。
- 新增或编辑时在右侧抽屉填写服务商、展示名称、真实模型 ID、Base URL、API Key 和类型相关参数。
- 编辑已有模型时，API Key 留空表示保留原密钥；输入新值表示替换，并明确提示保存后无法再次查看。
- “测试连接”作为直接行操作；编辑和删除收纳到更多菜单。
- 官方模型只在管理员工作台管理，个人模型只在个人设置管理，两者不得混合展示。

### 11.3 全站导航

- 全站统一导航层级、返回逻辑和账户入口，但不强制所有区域使用相同外观。
- 书架与个人设置共用顶部应用栏，承载 PenMate 品牌、书架入口、全局搜索、主题切换和账户菜单。
- 写作工作台使用更紧凑的项目栏，只保留返回书架、作品名、写作 / Story Bible 切换、保存状态和作品设置，避免占用正文空间。
- 管理员工作台继续使用独立左侧导航，并与普通用户区域保持明确的视觉和权限边界。

### 11.4 个人设置

个人设置最终分为以下六个区域：

- 个人资料：头像、昵称、个人简介和登录邮箱。
- 外观与编辑器：主题模式、正文默认字体、字号、行高、段间距、编辑区宽度，以及打字机模式和当前段落高亮的默认开关。
- 模型服务：管理个人服务商、API Key、模型列表和连接测试，只负责确定哪些模型可用。
- 默认模型与 Agent：选择创作模型、上下文筛选模型、Embedding 模型和少量真正影响 Agent 行为的偏好，只负责确定默认使用哪个模型。
- 安全：修改密码、已登录设备和退出其他设备。
- 数据与账户：作品导出、回收站入口和注销账户。

桌面端使用左侧分区导航，移动端使用顶部下拉分区。每个分区独立保存，并明确显示未保存、保存中、保存成功和保存失败状态。模型接入与模型选择不得混在同一张复杂表单中。

### 11.5 外观与布局偏好的数据归属

- 新增独立的 `user_ui_preferences`，保存需要跨设备同步的账号级偏好，不写入用户主表，也不与模型偏好混用。
- 后端同步主题模式、编辑器字体、字号、行高、段间距、正文宽度、打字机模式默认值和当前段落高亮默认值。
- 三栏具体宽度、折叠状态和最后使用的布局预设只保存在当前设备的 `localStorage`。
- 设备级布局按用户、作品和写作 / Story Bible 模式隔离，避免不同作品和工作模式相互覆盖。
- IndexedDB 只承担正文崩溃恢复草稿，不保存通用外观或布局设置。

### 11.6 作品级上下文路由

作品设置向用户提供三种 Story Bible 上下文路由模式，但使用可读名称，不直接暴露内部枚举：

- 智能筛选（`LLM_SELECTOR`）：由上下文筛选模型从设定目录中选择相关内容，不依赖向量索引。
- 语义检索（`RETRIEVAL`）：只使用 Embedding 向量检索，必须已有可用索引。
- 混合筛选（`RETRIEVAL_THEN_LLM`）：先向量检索，再由上下文筛选模型二次选择，必须已有可用索引。

后端只保存一个实际路由模式，不区分目标模式与生效模式。没有可用索引时只能保存和使用智能筛选；Embedding 模型变化会直接将模式改回智能筛选。索引重建完成后，用户需要手动重新选择语义检索或混合筛选。

### 11.7 单作品设置页

单作品设置使用独立页面，从工作台项目栏进入，桌面端使用左侧分区导航。页面包含：

- 基本信息：封面、作品名、简介、类型和标签。
- AI 与上下文：创作模型、上下文筛选模型、Embedding 模型和路由模式；三个模型分别支持继承账号默认或指定作品模型。
- 上下文索引：索引状态、当前 Embedding 模型、上次完成时间、失败原因和“重建索引”。
- 数据管理：导出 TXT 和 DOCX。
- 危险操作：将作品移入回收站。

上下文索引页不向普通作者暴露分块大小、Top K、相似度阈值和 HNSW 等技术参数。作品设置不包含账户安全、个人模型管理、编辑器外观、文风或插件，避免与账号设置和延期模块重复。

作品基本信息中的分类规则为：

- 类型为单选，内置玄幻、奇幻、武侠、仙侠、都市、历史、科幻、悬疑、言情、现实、轻小说和其他。
- 选择“其他”时允许填写一个自定义类型。
- 标签由用户自由输入，每部作品最多 10 个，单个标签最多 12 个字符。
- 标签保存前去除首尾空格并拒绝同名重复。
- 类型用于书架主要分类和筛选，标签用于更细的个人整理。
- 不新增全局标签管理页面，作品标签与 Story Bible 标签使用不同数据结构和作用域。

作品封面规则为：

- 支持 JPG、PNG 和 WebP，单文件最大 10 MB；不允许上传 SVG，GIF 不保留动画。
- 上传后使用固定 `2:3` 比例裁切，可缩放和移动图片，不提供任意比例。
- OSS 保存原图，后端异步生成 WebP 展示图和书架缩略图，以便后续重新裁切并减少加载体积。
- 处理期间显示本地预览；上传或处理失败时保留原封面并提供重试，不能先清空旧封面。
- 支持移除已上传封面；移除后恢复系统生成的文字封面。

作品设置按分区独立保存：

- 基本信息中的作品名、简介、类型和标签通过一个请求原子保存。
- 封面在裁切确认后单独上传并立即生效。
- AI 与上下文中的三个模型覆盖和路由模式通过一次请求原子保存，不逐字段即时生效。
- 更换或移除 Embedding 模型时，确认内容明确说明索引将失效、路由将切回智能筛选；确认后在一次事务中完成配置更新和索引失效标记。
- 重建索引、导出和移入回收站属于独立命令，不受其他分区未保存表单影响。
- 离开含未保存修改的分区时进行拦截提示；保存成功后停留在当前分区。
- 不提供整页“保存全部”，避免一个区域的校验错误阻塞其他设置。

作品基本信息的编辑入口统一收敛到单作品设置：

- 工作台项目栏中的作品名只读，点击作品名或设置图标进入作品设置的基本信息分区。
- 作品名、简介、类型、标签和封面只在作品设置中修改。
- 书架卡片右键菜单提供“作品设置”，但不直接弹出改名输入框。
- 卷名和章节名仍只通过作品目录右键菜单重命名。

## 12. 移动端边界

- 移动端保留目录、正文编辑、自动保存、AI 锁定、AI 撤回和 Story Bible 核心能力。
- 不在窄屏同时展示三栏，改为“目录 / 正文 / AI”三个视图切换；Story Bible 在导航与详情之间切换。
- 面板拖拽调宽、复杂关系图编辑和管理员批量操作仅在桌面端提供。

## 13. 当前实现必须清理的问题

- 大量 Vue 和 Java 源文件存在中文乱码，必须统一修复编码和显示文本。
- 当前全局样式包含不适用于专业工作台的古风主题、发光、随机粒子和过度装饰。
- 当前章节正文、版本、发布、OSS 上传链路与本决策冲突，必须全链路删除，不能只隐藏前端入口。
- 当前作品目录同时写入 outline 与 chapter，缺少事务一致性。
- 当前书架前端字段与后端项目模型不一致。
- 当前正文撤销是手写全文快照数组，不适合作为最终编辑器历史实现。
- 当前 `draft_generation` 是缓冲式 Tool，无法支撑正文流式编辑。
- 当前 Story Bible 向作者暴露技术字段、关系代码和 JSON Patch。

## 14. 登录与账户

- 本轮只保留真实可用的邮箱密码登录。
- 公开注册、邮箱验证和忘记密码流程暂不实现。
- 删除当前无后端接口的注册页签和无效“忘记密码”链接，不能继续展示占位功能。
- 删除无实际作用的“记住我”选项。Access Token 有效期 30 分钟，只保存在前端内存；Refresh Token 使用 HttpOnly Cookie，采用连续 7 天未使用才过期的滑动有效期。
- 用户主动退出、修改密码或被管理员禁用时，相关登录态立即失效。
- 新增 PostgreSQL `auth_sessions` 作为设备会话真源，记录稳定 Session ID、用户、Refresh JTI 哈希、设备信息、创建时间、最后活动时间、滑动过期时间和撤销时间。
- Refresh JWT 绑定 Session ID，RT 轮换通过原子条件更新完成，防止多标签页或重放请求同时消费同一旧 RT。
- 前端在 AT 到期前主动刷新，并保留 401 兜底；同标签页合并请求，多标签页通过 `BroadcastChannel` 协调刷新和同步新 AT。
- 个人安全设置展示已登录设备，并支持退出单个设备及退出所有其他设备。
- 昵称和简介可以直接修改；登录邮箱变更必须验证当前密码。邮箱修改成功后撤销所有其他设备会话，并要求用户使用新邮箱重新登录。本轮不发送邮箱确认邮件。
- 用户可以自行注销账户，但必须验证当前密码并明确确认。账户进入 30 天待删除期，期间禁止登录但管理员可恢复；到期后永久删除账号和个人模型密钥，并由数据清理任务处理作品内容。注销前提供作品导出入口。

## 15. 公开首页

- 保留公开官网首页，但只承担产品介绍和登录入口，不制作冗长营销页面。
- 已登录用户访问 `/` 时直接进入书架。
- 未登录用户看到 PenMate 品牌、真实工作台截图、核心能力和登录按钮。
- 本轮不开放注册，因此不展示“免费开始”等无效注册行动按钮。

## 16. 数据库变更策略

项目尚未上线，本轮所有数据库结构调整直接修改现有建表 SQL，并以全新数据库初始化作为验收基线。不新增兼容 Flyway 迁移，不保留旧字段、旧表或数据搬迁逻辑。

## 17. 快捷操作

- 本轮不提供全局命令面板。
- 不增加一套需要用户额外学习的全局导航和功能触发快捷键。
- 快捷键只服务于正文编辑器的通用编辑行为，并按操作系统惯例实现：
  - `Ctrl/Cmd + S`：立即同步当前章节。
  - `Ctrl/Cmd + Z`：撤销。
  - `Ctrl/Cmd + Shift + Z`：重做；Windows 额外支持 `Ctrl + Y`。
  - `Ctrl/Cmd + F`：查找。
  - `Ctrl/Cmd + H`：查找替换。
  - `Esc`：关闭查找替换、菜单或当前浮层。
- 不为新建章节、删除、专注模式、AI 操作或视图切换分配自定义快捷键。

## 18. 无障碍基线

本轮不以形式化认证为目标，但核心创作流程按 WCAG 2.2 AA 的实用要求实现：

- 浅色和深色主题中的正文、按钮、边框与状态提示保持足够对比度。
- 按钮、表单、菜单、抽屉和对话框可使用键盘操作，并提供清晰焦点。
- 图标按钮具有可访问名称和悬浮说明。
- 保存、错误、离线和 AI 锁定等状态不能只依赖颜色表达。
- 对话框正确管理焦点，关闭后将焦点还给触发控件。
- 支持操作系统的“减少动态效果”设置。
- 三栏拖拽之外提供键盘可用的宽度调整方式。
- Story Bible 关系图提供等价关系列表，不要求读屏软件直接操作图形画布。
- AI 流式生成不逐字符触发读屏播报，只播报开始、完成、失败和取消等关键状态。

## 19. 全站状态与反馈

- 首次加载保留页面结构并在局部显示骨架屏，不使用全屏加载遮罩阻断整个应用。
- 局部刷新保留已有内容并显示小型加载状态，避免页面闪空。
- 空状态说明为空的原因，并只提供一个最相关操作；缺少后端能力时明确显示“暂未接入”，不使用伪造数据。
- 字段校验错误显示在对应字段下方；保存失败在表单操作区持续显示并提供重试。
- 页面或列表加载失败在失败区域原位显示原因和重试，不能只依赖短暂消息。
- 短暂成功反馈使用轻量消息；自动保存成功主要由编辑器状态栏表达，不频繁弹出提示。
- 危险操作使用确认对话框；普通且可逆的操作优先在完成后提供撤销。
- 网络离线时正文继续写入 IndexedDB 并持续显示离线状态；其他写操作必须明确禁用或排队，不能假装成功。
